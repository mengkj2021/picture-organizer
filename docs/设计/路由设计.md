# 路由设计

> 「图片整理」App 导航设计总览。导航基于 **单 Activity + Jetpack Compose + Navigation Compose**（依赖 `androidx.navigation:navigation-compose`，开发画面时引入）。本文档维护统一的 route 命名与导航图，画面文档见 [`docs/画面/`](../画面/)。

## 1. 技术选型

- 单 Activity 架构，每个画面是一个 Composable
- 导航库：Navigation Compose（已引入）
- Application 级 Room 初始化见 [架构设计.md](架构设计.md)
- 式样书画面清单见 [项目式样说明书.md](../式样/项目式样说明书.md) 第 5 章
- route 以字符串常量集中定义，避免散落硬编码

## 2. route 命名约定

| 规则 | 示例 |
|---|---|
| 全小写，多词用连字符 | `import-images` |
| 传参用路径参数，`{}` 包裹 | `detail/{imageId}` |
| 根画面固定为 `splash` | `splash` |

## 4. 新增画面流程

1. 复制 `docs/画面/_模板/` → `docs/画面/xxx画面/`，填写 `README.md` 并按需增加区域文件
2. 在本文档第 3 节画面表中登记 route（文档列指向该目录 `README.md`）
3. 更新《项目式样说明书》第 5 章画面清单（[`docs/式样/项目式样说明书.md`](../式样/项目式样说明书.md)）
4. 开发时注册路由并实现 Composable

## 5. 系统返回动作统一约定

| 层级 | 默认行为 |
|---|---|
| 非根画面 | 返回键 = 返回上一画面（`popBackStack()`） |
| 根画面（main） | 返回键 = 退出应用（系统默认） |
| splash | 自动跳转至 main，不在 back stack 保留 |
| 带编辑 / 未保存内容 | 返回时用 `BackHandler` 拦截并提示确认，由各画面文档约定 |
