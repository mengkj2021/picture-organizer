# AI 配置扩大方向（大项目 / 文档变厚时）

> **定位**：演示与预留——当前仓库以 [`shared/AI配置落位.md`](../../shared/AI配置落位.md) 的**薄架子**为准即可；本文说明**体量变大时**往哪加厚，避免临时发明第二套控制面。  
> **关联**：F30；勿与 F24（防规则膨胀）冲突——加厚优先进 prompts/skills/docs 结构，而非常驻 rules。  
> **不是**：GSD 全量搬迁、`.planning/`、每票强制多 Agent。

---

## 1. 何时该扩大（信号）

出现多数即考虑加厚（仍保持落位四象限）：

- 单次接票常漏读关键章节，或上下文被整份长文撑爆  
- 式样 / 画面文档页数明显上升，索引不够用  
- 同一类 SOP（新画面、发版、依赖升级）重复口述  
- 多人 / 多 AI 并行，需要更清晰的「必读清单」与模块边界  

当前 picture-organizer **未强制**下列各项；有信号再按需启用。

---

## 2. 扩大方向（按通道）

### 2.1 rules（仍然要短）

| 可加 | 仍禁止 |
|---|---|
| 更多「红绿灯」短句（如模块所有权、禁止通读某巨文件） | 粘贴式样/架构章节正文 |
| 指向落位文档 / 扩大本文的一句话链接 | 每画面一条 alwaysApply |

原则：**条数可略增，单条必须短；总量受 F24 约束。**

### 2.2 prompts（主扩容区）

| 方向 | 说明 |
|---|---|
| **本票必读清单**强制化 | 功能开发已具备雏形；大项目可要求清单必须含「文件 + 章节锚点」 |
| **分档提示词** | 绿/黄/红（或 Fast/Quick/Full）不同填写模板，红档加长澄清与步骤确认 |
| **专题 prompt** | 如「仅迁移」「仅安全审计」「仅发版检查」——拉入才跑，不常驻 |
| **起票时拆票检查表** | 与 F29 门槛对齐，放大到独立填写区 |

### 2.3 skills（按触发扩容）

| 方向 | 说明 |
|---|---|
| 落地 F21/F22 及 README 中规划技能 | 新画面、实现、对文档、改依赖 |
| **读长文档 SOP** | 输入：票号；输出：必读路径表；禁止通读 |
| **模块地图 skill** | 大包结构下按 feature 列出默认必读文件（仍引用 docs，不复制） |
| 同步到各 IDE 技能目录 | 见 `shared/skills/README.md` |

### 2.4 docs 自身（真相源扩容）

| 方向 | 说明 |
|---|---|
| 长文拆目录 / 区域文件 | 已有 `docs/画面/<画面>/` 模式，继续推广 |
| 每份权威长文加「AI 阅读入口」小节 | 3～7 条锚点：接票时优先打开这些节 |
| 票「关联」写到章节级 | 减少「去读整本式样」 |
| 索引页（`docs/README`）保持薄 | 分类入口，不堆正文 |

### 2.5 可选进阶（真很大再考虑）

- 轻量「当前焦点」一页（类似 STATE，仍可用票 🚧 + 改动清单，不必上 GSD）  
- 红档一拍一会话（Discuss/Plan/Execute/Verify 分会话，文件交接）  
- feature 分支约定（见 F29）  
- 知识图谱 / Codebase MCP 等外部检索——**替换盲目 grep，不替换 docs 真相**  

---

## 3. 扩容时的反模式（demo 也避免）

1. 为「看起来专业」把 GSD 学习长文整仓入库  
2. 式样与 rules 双份维护，必然漂移  
3. 十几个空 skill 目录无 SOP  
4. 常驻 rules 回潮成第二份说明书  
5. 未锁需求就上 Autonomous / 多 Agent 并行改同一模块  

---

## 4. 与本 demo 的关系

| 现在（薄） | 将来（厚） |
|---|---|
| 落位矩阵 + 读法短纪律 + 必读清单一步 | 章节级清单、分档 prompt、多个真 skill |
| skills 仅框架 + 指向 F21/F22 | skill 正文落地并双工具同步 |
| 本文作预留 | 按 §1 信号逐项启用，每项可再起票 |

**一句话**：架子证明「AI 工程化怎么分层」；本文证明「大了往哪长」——长在 prompts/skills/docs 结构上，而不是把大书塞进 rules。
