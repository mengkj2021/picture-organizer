# 起票模板（目录）

> 只负责「把一张票立起来」的操作说明。票库规则见 [`../README.md`](../README.md)。

## 起票步骤

1. **定票号**：查目标分区的台账表（如 [`../bug/README.md`](../bug/README.md)），沿用序号（Bug2、S2、T1、F1 起）。
2. **复制模板**：复制本目录对应类型模板 → 到分区目录下新建 `票号-简述/`，模板文件改名为该目录的 `README.md`。
   ```
   cp bug票.md ../bug/Bug2-打包导出漏文件/README.md
   ```
3. **填写**：删除模板顶部说明行，填「票信息」、**关联画面·预估**（对照 `docs/画面/`）与正文（现象 / 复现、或变更内容、或调查问题、或功能诉求），补验收标准。  
   「实际改动」栏起票时留空，由接票收尾填写。  
   「档位 / 已锁定 / 实施步骤」接票时填；**绿档**可省略已锁定、步骤写「一步完成」。拆票门槛见 [`功能开发.md`](../../../shared/prompts/功能开发.md)。
4. **登记台账**：在分区 `README.md` 的台账表追加一行（票号 / 标题 / ☐ / 目录链接）。
5. **等待接票**：把该票目录（或票内容）交给开发对话，按 [`../../../shared/prompts/功能开发.md`](../../../shared/prompts/功能开发.md) 执行。

## 模板列表

| 类型 | 模板 | 用途 |
|---|---|---|
| Bug 票 | [bug票.md](bug票.md) | 已确认的错误行为 |
| 式样变更票 | [式样变更票.md](式样变更票.md) | 已确认要改的式样 / 需求变化 |
| 调查票 | [调查票.md](调查票.md) | 问题不明，先调查再定方案 |
| 功能 / 体验票 | [功能体验票.md](功能体验票.md) | 新功能（C）或体验增强（P） |

## 约定

- 票号与类型**只进不退**：❌ 不采纳的票不再复用其号。
- 目录标题过长的，票内「标题」栏写全名，目录名用摘要。
- 模板已内置「完结复盘」节（文件末尾）：验收（✅ / ❌）后由开发对话填写（Bug 原因 / 式样利弊 / 调查结论 / 效果代价）；**票与台账行不删除**，只流转状态。
- 有复用价值的教训登记 [`docs/工程/错题本.md`](../../错题本.md)，票内注明登记与否。
- **母题 / 子票**：子票用新号、关联写母题；写法见 [`../README.md`](../README.md)「母题与子票」。
