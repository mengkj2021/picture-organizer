## 用户诉求 / 场景

- **现状（写实）**：
  1. 库**没有「导入前原图名」字段**：`fileName` / `description` 导入时都存 F1 清洗截断后的落盘名，原始显示名（Uri `DISPLAY_NAME`）只用完即弃；
  2. **无任何按名判重**：重复导入 = 新增一条记录（F3 只做了顶部静态文案「重复导入会生成另一条记录」）；磁盘文件防冲突（同名落盘名加 UUID 短后缀）是唯一"撞名"处理；
  3. 导入单张只查磁盘 `exists()`，从不查库。
- **预期效果**：
  1. 导入时把**原图名**记录入库（新增字段），后续导入按原图名与库中已导入图片对比；
  2. 一批导入时：**先把无重名冲突的图片导入**；原图名与库中已有（含本批已导入的）相同的，**一对一对弹出询问**「这张图片原先导入了同样名字的图片，是否要导入」——继续则照常导入（落盘名冲突仍走现有短后缀），否则跳过该张；
  3. **询问开关**（DataStore 布尔，默认开=询问拦截）：关闭后不询问直接导入（行为同现状）；
  4. 开关在**设置画面**配置；询问弹窗内显示提示（如「可在 设置 → 导入 中关闭此询问」）。
- **是否已有式样依据**：否，新功能；F3 文案与范围（不去重不覆盖）是既有约定，本票在「询问」层新增，不改变"重复仍可导入为另一条记录"的最终语义（用户选择导入 → 仍新增一条）。

## 需求确认（接票前若为「待定」先在此澄清）

- **原图名字段**：`ImageEntity` 增列（如 `originalName`），DB 迁移 v3→v4；仅新导入写入（Uri `DISPLAY_NAME`）。**不回填历史记录**（用户已拍板）：旧行 `originalName` 为 null，判重仅对两行均有值时生效——本功能对历史图不追溯，只保护从今往后的导入（局限写明，不做 description 回填以免截断/短后缀失真）。
- **判重口径（用户拍板：大小写不敏感、含批内）**：比较对象 = 库中所有状态图片 + **本批已导入（批内同名也进询问队列）**；原图名**大小写不敏感**比较（含扩展名，`IMG_001.JPG` ≡ `img_001.jpg`）；本批先导"不与库冲突也不与本批冲突"的，冲突对逐张询问。原图名超长由 F1 截断只影响落盘名，不影响原图名比较。
- **询问交互（用户已拍板加「本次不再询问」）**：暂停式逐张询问，弹窗动作 = `跳过这张` / `导入这张` / `本次不再询问`。**「本次不再询问」仅对当前这批生效**：点后本批剩余重名图不再弹窗、照常导入，不改全局开关（全局开关在设置画面，另管是否开启询问）。
- **开关位置**：用户指定设置画面 → `SettingsScreen` 现为**纯导航 LazyColumn 无开关行**，需扩展支持 Switch 行并同步更新设置画面文档（数据依赖「纯导航」需改写）。
- **开关与弹窗文案**：弹窗内提示设置入口的文案、设置项名称（「导入重名询问」）待定。

## 验收标准

- [ ] 导入时原图名入库；新导入的同名原图可被判出
- [ ] 一批含重名：无冲突的先导入，冲突的逐张弹窗询问；导入 → 新增另一条记录，跳过 → 不导入

- [ ] 开关默认开；设置画面关闭后导入不再询问（照常导入）
- [ ] 弹窗内含「可在设置中关闭」提示
