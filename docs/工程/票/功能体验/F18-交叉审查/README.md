## 用户诉求 / 场景

- 要解决的问题或场景：自审效果有限——"写和审是同一个脑子，思维盲区一样"（业界交叉审查共识）；项目恰有 CodeBuddy + Cursor 双工具，可让 A 写的交给 B 审（反向亦可），不同模型盲区不同，比自审更能抓"多余抽象 / 不符合包结构 / 漏边界 / 做了错误的事"。
- 预期效果：一张可拉入对话的固定审查 prompt（只改填写区：审查对象 diff / 票号），规定审什么、输出什么，审出问题回接票改。公开叙事上也是"双 AI 交叉审查"亮点素材。
- 是否已有式样依据：否（流程/工具资产）。

## 需求确认（接票前若为「待定」先在此澄清）

- 范围：新建 `shared/prompts/交叉审查.md`（沿用 prompts 模板约定：上半固定流程、下半填写区）；**不建 CI、不改功能开发.md 强制流程**（本票只提供可选工具，是否纳入强制由使用效果决定）。
- 审查清单建议固定项：① 是否加了不必要的抽象 / 重复造轮子；② 是否符合包结构与现有代码模式（dev-convention）；③ 边界与错误分支是否处理；④ 对照票「验收标准」——做的是不是票上要的事；⑤ 是否引入漂移（改了不该改的）。
- 输出格式建议：按清单逐条「通过 / 问题 + 文件位置 + 建议」，无问题才可视为通过。
