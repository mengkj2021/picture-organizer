## 用户诉求 / 场景

- **要解决的问题或场景**：应用 UI 文言目前仅中文（`values/strings.xml`）。面向中日英用户时，需按语言显示对应文案。
- **预期效果**：
  1. 提供 **中文、日文、英文** 三套 UI 文言资源；
  2. 用户可见界面（标题、按钮、提示、空态、错误分类文案等）随语言切换；
  3. 缺译时有明确回退策略（建议回退默认中文或英文——接票定）。
- **是否已有式样依据**：否；本票起式样，接票时补式样书章节。

## 需求确认（接票前若为「待定」先在此澄清）

- **语言来源（待定，建议 A）**：
  - **A**：跟随系统语言（`values` / `values-ja` / `values-en`），不做应用内开关——改动小、符合 Android 惯例；
  - **B**：设置内增加「语言」选项（系统 / 中 / 日 / 英），需 DataStore + `AppCompatDelegate.setApplicationLocales`（或等价）——体验更可控，改动面更大。
- **中文变体（待定，建议简体）**：默认 `values` = 简体中文；是否另做 `values-zh-rTW` 繁体——**本票建议不做**，仅简中 + ja + en。
- **范围边界（待定，建议如下）**：
  - **纳入**：`strings.xml` 全量 UI 文言；Kotlin 中误硬编码的用户可见字符串收口到资源；
  - **不纳入（或另票）**：用户自建标签 / 文件名 / 重命名模板内容（用户数据不译）；仓库 `docs/` 文档保持中文；开发日志 / 票库中文；
  - **慎纳需确认**：`ImageListItem.STATUS_TAGS`（「待处理」「已确认」「回收站」）是**数据层保留字**兼历史显示名——是否仅 UI 显示名本地化、库内仍存中文键，接票时定方案，避免破坏筛选 / Exif / S1 约定；
  - **教程画面**：教程正文若在 string / Compose 硬编码，是否本票一并三语——建议本票纳入 UI 壳层文案；长文教程可与 **F12** 协调或本票一并译。
- **翻译质量（待定）**：首版可由 AI 起草日/英译，用户抽检关键画面；是否需要专业校对——非阻断，可标遗留。
- **与 F27 / F26**：设置底部版本号、OssLicenses 画面若后做，其新 string 须同步三语资源（或本票后约定「新增 string 必补 ja/en」纪律）。
