## 用户诉求 / 场景

- 要解决的问题或场景：业界（Spec-Driven 2026）共识——**diff 审查回答「代码写得对不对」，spec 审查回答「做的是不是票上要的事」**。AI 代码往往"格式整洁但做错了问题"，目前收尾只做 diff 级自检 + 回写票状态，缺"逐条对照验收标准自评"的强制一步。
- 预期效果：接票收尾时 AI 先逐条对照票的「验收标准」自评勾选（含行为可证项），有不达标的先补齐，全部达标才回写 ✅ / 提交验收。让"做对的事"成为流程硬步骤而非自觉。
- 是否已有式样依据：否（流程改造，不涉产品式样）。

## 需求确认（接票前若为「待定」先在此澄清）

- 范围：只改 `shared/prompts/功能开发.md` 的收尾流程，新增「验收对照自评」步骤；不改票模板、不改验收条目写法。
- 自评动作：读完票「验收标准」→ 逐条写「证据」（改了哪、验证了什么）→ 全部 ☑ 才可回写状态；有 ☐ 未达标 → 先补做再收尾。
