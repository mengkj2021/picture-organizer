## 用户诉求 / 场景

- 要解决的问题或场景：`dev-convention.md` 为 alwaysApply（每会话常驻注入），目前较长、包结构等细节全量载入。业界（CLAUDE.md best practices）共识：常驻文件只放高频真理、低频细节按需加载（globs / 技能 / 链接），否则每会话白白烧上下文，规则越长 AI 遵守率越低。
- 预期效果：`dev-convention.md` 收敛为高频核心约定（文档先行、一票一会话、先测后写引用等）；包结构、构建细节等低频内容挪到按需文档（或已有权威文档引用），需要时 AI 现查，不常驻。
- 是否已有式样依据：否（工程整理）。

## 需求确认（接票前若为「待定」先在此澄清）

- 范围：只重组 dev-convention 的**内容分布**（哪些留常驻、哪些移走/改引用），**不新增约束**、不改语义；其他 rules 文件不在范围（各自按需另评）。
- 原则：保留引用链（移到哪就在原位置留一句"见 xxx"），避免移走后找不到；所有内容仍可被 AI 定位到，只是不再全量注入。
