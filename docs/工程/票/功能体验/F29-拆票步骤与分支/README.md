## 用户诉求 / 场景

- **要解决的问题**：对照 GSD 后，本仓库已有票驱动 / 四拍轻量版，但缺显式约定——（1）大票何时拆成多张可独立验收的小票；（2）小票内如何用步骤表管上下文与提交切片；（3）红黄档是否/如何用 Git 分支隔离半成品；（4）**起票预估 / 收尾记录关联画面文档路径**。现状易靠默契，且 git-convention 未覆盖 feature 分支。
- **预期效果**：
  1. 有可执行的**拆票门槛**与母题/子票关联写法（子票用**新号**，关联写母题）；
  2. 票模板与接票流程支持**实施步骤表**（步骤 ≠ 无限子票）；接票先确认步骤/清单再写码；
  3. **绿 / 黄 / 红**档对应分支策略：`ticket/Fxx-简述`；merge/push 仍由用户决定；
  4. 票模板含**关联画面·预估 / 实际改动**（路径级）；起票分析与功能开发强制填/回写；
  5. **不引入** `.planning/`、不强制每票四窗口 / Autonomous；遵守 F19 / F24。
