## 4. 核心功能（已确认）

- 图片处理流程：**导入 →（可选）压缩保存 → 单张图片操作 → 按标签分类导出**

### 4.1 导入

- 图片需用户**手动导入**到 app 私有目录（复制，非移动）
- 导入来源支持两种：**系统相册 / 图库** 与 **文件选择器**
- 导入时可合并 **默认标签**（DataStore，见设置 → 默认标签；**C9**）
- **实现状态：已实现**（route `import-images`）

### 4.2 导入时压缩

- 判断标准：**文件大小或像素分辨率任一超过阈值即压缩**（两者结合判断），未超阈值保留原样
- 压缩阈值（**临时，可后期调整**）：
  - 文件大小 **> 2MB**，或
  - 长边 **> 1920px**
  - 压缩输出：JPEG，质量约 **85**
- 导入画面提供「按规则压缩」开关（默认开，DataStore `import_compress_enabled`；关则原样复制）（**C10**）

### 4.3 单张图片操作（当前阶段）

- 支持：**重命名**（含套用重命名模板）、**加标签**（库多选 / 套用标签模板 / 自由输入）
- 状态整理（**S1 状态不算标签**）：「待处理 / 已确认 / 不修改」仅由 `status` 字段 + 主画面三 Tab 分类表达，**不**写入图片标签 / `tagsJson` / Exif；移动图片到目标 Tab 即完成状态整理，无独立「完成」标签
- 标签双写：Room `tagsJson` 为 UI 真源（**仅存用户标签**）；用户标签同步写入 JPEG Exif `UserComment`（UTF-8 JSON 数组）
- **S2**：详情自由输入添加标签成功后，若标签库无同名则自动写入标签库；已存在则跳过
- **F1**：导入落盘文件名取自源 DISPLAY_NAME，主名清洗并截断最多 40 字符，冲突时追加短后缀；压缩输出仍可为 `.jpg`
- **F6**：列表可按「文件名包含」筛选，并按文件名或导入日期排序（默认导入日期新→旧）；主画面与打包共用 `filter`；首期不含日期区间
- 剪切：不纳入当前阶段，列为以后扩展
- **实现状态：已实现**（画面 `image-detail/{imageId}`）

### 4.4 按标签分类导出

- 按标签将**已确认**图片分组，**每个标签单独生成一个压缩包（zip）**（「未打标签」可单独一包）
- 输出目录：`filesDir/exports/`；经 **FileProvider** 调用系统分享；用户也可通过系统文件管理器拷出
- App 内入口：**已确认菜单 → 打包导出**（route `export-zip`，**C7**）
- 打包前可复用筛选画面 `filter` 配置标签条件
- **实现状态：已实现**

## 6. 文件整理方案（已确认）

- 整理方式：**直接操作文件夹** —— 移动 / 重命名真实文件，按规则归类。
- 图片存放在 app 私有目录 `filesDir/images/` 下**三子目录**（单表 `images` + `status`）：
  - `pending/` — 待处理
  - `confirmed/` — 已确认
  - `no_modify/` — 不修改
- 导入写入 `pending/`；「移动到」同步搬文件并改库；「删除」删文件并删行
- 导出 zip 存入 `filesDir/exports/`，经 FileProvider 分享；全程本地运行，**不联网**，无网络权限需求
