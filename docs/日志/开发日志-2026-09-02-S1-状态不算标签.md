# 开发日志 · 2026-09-02 S1 状态不算标签

## 背景

原实现把状态词（待处理 / 已确认 / 不修改）作为「状态标签」注入 `ImageListItem.tags` 并写入 Room `tagsJson`：详情保存、移动、导入时都会把状态词拼进标签首位。多数读端已用 `userTagsOf` 过滤，但存在漏点与脏数据，且与式样书旧条款「确认完成也是一个标签」冲突。

S1（改动清单 · 式样变更）定稿：**状态仅由 `status` 字段 + 主画面三 Tab 分类表达，不作为标签出现在标签库 / `tagsJson` / 筛选 / 打包用户标签中**。

## 改动

### 代码（7 文件）

- `model/ImageListItem.kt`
  - `withStatus`：不再注入状态标签，仅切换 `status` 并剔除 tags 中的状态词（顺带清洗历史残留）
  - 删除 `statusTagFor`；`STATUS_TAGS` 保留，语义改为「三个状态名为保留字，禁止作为用户标签 + 对历史数据兜底过滤」
  - `userTagsOf` 保留（读端防御旧数据）
- `data/mapper/ImageMappers.kt`：删除 `tagsForStatus`（写端不再注入状态标签）
- `data/repository/RoomImageRepository.kt`
  - `insert` / `updateTags`：只存用户标签（`userTagsOf` 清洗兜底）
  - 启动迁移 `migrateFlatPathsIfNeeded` 循环内：幂等剔除存量 `tagsJson` 中残留的状态词
- `data/repository/MockImageRepository.kt`（Preview）：`insert` / `updateTags` 同 Room 一致只存用户标签
- `ui/imagedetail/ImageDetailViewModel.kt`：`persistTags` 不再前置状态标签
- `ui/main/tab/ImageListItemRow.kt`：标签 chip 改渲染 `userTagsOf(item.tags)`（修复状态词以 chip 出现在列表的问题）；Preview mock 去状态词
- `data/mock/MockImageListData.kt`：`item()` 统一剔除状态词，mock 形态即 S1 后数据
- `app/src/main/res/values/strings.xml`：详情保留字提示文案改为「状态名不能用作标签」

## 行为保持

- 详情仍禁止把「待处理 / 已确认 / 不修改」输入为用户标签（保留字提示）
- 三 Tab 划分、移动、删除、打包、Exif 双写、重命名 `{tag}`、筛选「未打标签」行为不变（读端早已按用户标签处理）
- 存量 Exif 不回写（读端 `readUserTags` 已过滤）；存量 Room 由启动迁移一次性清洗

## 验收

1. 新导入 → DB `tagsJson` 无状态词；主画面 chip 只显示用户标签
2. 移动（待处理 → 已确认 等）后 `status` 更新、`tagsJson` 不含任何状态词，用户标签原样保留
3. 详情增删改标签 / 库多选 / 套模板 → `tagsJson` 无状态词；输入状态名仍被拒并提示
4. 打包分组、筛选、重命名 `{tag}`、Exif 回读均不出现状态词
5. 升级自旧版本（`tagsJson` 残留状态词）后：列表 chip 不再显示状态词，任一次写操作后 DB 即干净
