## 3. 遇到的问题与解决方案

### 3.1 首次构建：13 个 AAR metadata 错误（依赖要求 compileSdk ≥ 34）

- **现象**：androidx.activity 1.8.2 等依赖要求 compileSdk ≥ 34，而模板 compileSdk = 33
- **排查**：先按"降级路线 A"把 core-ktx / lifecycle / activity 降到旧版本，错误从 13 降到 1
- **结论**：降级只能治标，最终放弃，改走"整体升级路线 B"

### 3.2 emoji2 1.4.0 压制无效

- **现象**：Compose foundation 1.5.4 传递依赖 emoji2 1.4.0（要求 compileSdk 34）。显式声明 1.3.0 后，Gradle 冲突解决仍取最高版本 1.4.0（`1.3.0 -> 1.4.0`）；用 `resolutionStrategy.force` 强制也无济于事
- **处理**：升级路线下该冲突随 Compose 1.12.0 一并消失，相关压制代码已从构建文件移除

### 3.3 Gradle 9.7.1 下载超时（SocketTimeoutException: Read timed out）

- **原因**：国内直连 `services.gradle.org` 下载 130MB 发行包很慢，且 `gradle-wrapper.properties` 默认 `networkTimeout=10000`（10 秒）太短
- **处理**：
  1. `networkTimeout` 调大到 600000（10 分钟）
  2. 验证腾讯云 / 华为云镜像，均只同步到 4.x/5.x，**没有 9.7.1**，镜像方案不可行
  3. 最终：手动下载 zip 到 `D:\gradle\gradle-9.7.1-bin.zip`，`distributionUrl` 改为本地文件 `file:/D:/gradle/gradle-9.7.1-bin.zip`，wrapper 从本地解压安装，不再联网

### 3.4 AGP 9.3.2 超出 AS 支持上限

- **现象**：AS 提示 `The project is using an incompatible version (AGP 9.3.2). Latest supported version is AGP 9.2.1`
- **处理**：AGP 降为 **9.2.1**。经核实：AGP 9.2.x 要求 Gradle ≥ 9.4.1（当前 9.7.1 满足），最高支持 API 37
- **经验**：AGP 选型受 Android Studio 版本支持上限约束，不是越新越好

### 3.5 14 个 AAR metadata 错误（依赖要求 compileSdk ≥ 37）

- **现象**：Compose 1.12.0（BOM 2026.08.00 引入）11 项、core / core-ktx 1.19.0 2 项、lifecycle 2.11.0 1 项，全部要求 compileSdk ≥ 37，而当时是 36
- **处理**：`compileSdk / targetSdk = 36 → 37`，与最新依赖矩阵的 minCompileSdk 对齐
- **经验**：最新版 androidx 依赖往往要求最新 compileSdk，升级依赖时需同步升级 compileSdk

## 5. 遗留事项与经验总结

### 遗留提示（可忽略）

- `android.overridePathCheck=true` experimental 警告：项目路径含中文（`项目列表`）所致，属性保留
- "Deprecated Gradle features ... incompatible with Gradle 10"：Gradle 9.7.1 运行提示，暂无影响

### 经验总结

- 国内网络下，Gradle 发行包优先采用**本地 zip + file:// 分发**，避免官网直连超时
- Android Studio 对 AGP 有**版本上限**，选型前先确认 AS 支持范围
- androidx 最新稳定版普遍要求 **compileSdk 同步到最新**，升级依赖时一并调整
- AGP 9 启用 **Built-in Kotlin**，无需再应用 `org.jetbrains.kotlin.android` 插件，Compose 编译器由 `org.jetbrains.kotlin.plugin.compose` 管理
