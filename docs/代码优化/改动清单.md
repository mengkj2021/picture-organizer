# 代码改动清单

> 用途：记录「图片整理」App 代码层面的优化项，作为后续开发的实施依据。
> 状态标记：☐ 待实施 ／ 🚧 进行中 ／ ✅ 已完成
> 关联：式样书 §7 未决事项「RoomImageRepository 接入与 Mock 替换」；架构设计 §3.2 目标数据流。

## A. 数据层打通（当前主线，架构设计 §6 第 1、4 步）

### A1 Room 接入 Repository（RoomImageRepository）

- **现状**：`AppDatabase` / `ImageDao` / `ImageEntity` 已就绪，但 UI 仍读内存 Mock（`MainViewModel` 默认注入 `MockImageRepository`）；数据库在 Application 启动时创建但从未写入 / 读取。
- **改动方案**：
  1. 新建 `RoomImageRepository : ImageRepository`（`data/repository/`）
  2. 实现 `getItems` / `moveItems`（内部走 DAO + Mapper）
  3. `MainViewModel` 默认注入改为 `RoomImageRepository`（Mock 保留用于 Preview / 测试）
- **涉及文件**：新建 `data/repository/RoomImageRepository.kt`；修改 `ui/main/MainViewModel.kt`、`PictureOrganizerApplication.kt`
- **前置 / 待定**：依赖注入方式（构造注入 or 简单 Service Locator，不引 Hilt）；Mock 保留位置见 A6
- **验收点**：`assembleDebug` 通过；三个 Tab 仍能显示列表；移动操作后重启 App 数据保持（持久化生效）

### A2 响应式数据流（Flow）

- **现状**：`ImageDao.observeByStatus()` 返回 `Flow`，但 `MainViewModel` 用 `refreshLists()` 同步拉取并手动 `copy` 进 state；`moveItems` 后手动调 `refreshLists()`。
- **改动方案**：
  1. `ImageRepository` 增加 `observeItems(status): Flow<List<ImageListItem>>`
  2. `MainViewModel` 用 `combine` / `flatMapLatest` 合并三个状态列表为单一 `StateFlow`
  3. 删除 `refreshLists()` 手动刷新
- **涉及文件**：`data/repository/ImageRepository.kt`、`data/repository/MockImageRepository.kt`、`data/repository/RoomImageRepository.kt`（新建）、`ui/main/MainViewModel.kt`、`MainUiState.kt`
- **前置**：A1、A3
- **验收点**：DAO 数据变化（move / insert 后）自动反映到 UI，无需手动刷新

### A3 Entity ↔ 模型 Mapper

- **现状**：`ImageEntity`（`status: String`、`tagsJson`）与 `ImageListItem`（`status: ImageStatus`、`tags: List<String>`）无转换层；`ImageListItem.withStatus()` 在 UI 模型里混入状态标签拼接业务逻辑。
- **改动方案**：
  1. 新建 `data/mapper/ImageMappers.kt`：`ImageEntity.toListItem()` / `ImageListItem.toEntity()`
  2. `status` String ↔ `ImageStatus` 映射（非法值兜底 `Pending`）
  3. `tagsJson` ↔ `List<String>` 转换复用 Converters
- **涉及文件**：新建 `data/mapper/ImageMappers.kt`；修改 `model/ImageListItem.kt`（状态标签逻辑移入 mapper 或保留）
- **前置 / 待定**：状态标签文案是否保留在 model（标签体系未定稿，见式样书 §7）
- **验收点**：双向转换 round-trip 一致（测试覆盖）

### A4 Converters 注册与实现

- **现状**：`Converters` 类存在但 `AppDatabase` 未标注 `@TypeConverters`（死代码）；用 `\u001F` 分隔符拼接标签（非 JSON）。
- **改动方案**：
  1. `AppDatabase` 标注 `@TypeConverters(Converters::class)`
  2. 或改用简单 JSON 存储（`org.json`，Android 内置）——需同步更新 `ImageEntity` 注释与架构设计 §4.2 `tagsJson` 说明
- **涉及文件**：`data/local/AppDatabase.kt`、`data/local/converter/Converters.kt`
- **前置**：无
- **验收点**：`@TypeConverters` 生效，`List<String>` 字段可被 Room 正确处理

### A5 DAO 补齐

- **现状**：`ImageDao` 只有 `observeByStatus` + `insert`；批量改状态、update、delete、按 id 查询均缺失，与 UI 的 `moveItems` 操作不对应。
- **改动方案**：新增
  - `@Query("UPDATE images SET status = :status WHERE id IN (:ids)") suspend fun updateStatus(ids: List<String>, status: String)`
  - `@Query("DELETE FROM images WHERE id IN (:ids)") suspend fun deleteByIds(ids: List<String>)`
  - `@Query("SELECT * FROM images WHERE id = :id") suspend fun findById(id: String): ImageEntity?`
- **涉及文件**：`data/local/dao/ImageDao.kt`
- **前置**：A1（注入后需要）
- **验收点**：批量移动 / 删除操作落到数据库

### A6 Mock 定位

- **现状**：`MockImageRepository`（内存三列表）+ `MockImageListData`（36 条假数据）是当前唯一数据源；`ImageListTab.kt` 的 Preview 直接引用 `MockImageListData`。
- **改动方案**：
  1. 主流程切到 Room 后，Mock 保留为：Preview 数据源 + 测试 fixture
  2. 明确删除时机：导入功能（`AppFileManager`）实现后不再需要
- **涉及文件**：`data/repository/MockImageRepository.kt`、`data/mock/MockImageListData.kt`、`ui/main/tab/ImageListTab.kt`
- **前置**：A1
- **验收点**：Mock 仅被 Preview / test 引用，无生产路径依赖

## B. 工程质量

### B1 单元测试

- **现状**：无任何测试。
- **改动方案**：
  1. 引入测试依赖：JUnit4、`kotlinx-coroutines-test`、Room in-memory（androidTest）
  2. 覆盖：`ImageMappers` round-trip、`RoomImageRepository`（in-memory DB）、`MainViewModel`（move / select / UI state）
- **涉及文件**：新建 `app/src/test/`、`app/src/androidTest/`；修改 `app/build.gradle.kts`（test 依赖）
- **前置**：A1–A5（依赖打通后测试才有意义）
- **验收点**：`./gradlew test` 全绿

### B2 Lint / 代码检查

- **现状**：无 lint 配置、无 ktlint。
- **改动方案**：`android { lint { abortOnError = true } }`；可选引入 ktlint（Spotless）并接入 Git 钩子
- **涉及文件**：`app/build.gradle.kts`（或根 `build.gradle.kts`）
- **前置**：无
- **验收点**：`./gradlew lint` 通过

### B3 release 构建优化

- **现状**：`isMinifyEnabled = false`，未开 R8 / 资源压缩。
- **改动方案**：release `isMinifyEnabled = true` + `isShrinkResources = true`；签名在发布时配置
- **涉及文件**：`app/build.gradle.kts`
- **前置 / 待定**：签名文件策略（本地生成、不提交 git，见提交注意事项 §4.2）
- **验收点**：release APK 体积显著下降且功能正常

### B4 隐私安全（备份）

- **现状**：`AndroidManifest.xml` 中 `android:allowBackup="true"`——App 整理真实图片，允许系统备份到云有隐私风险。
- **改动方案**：`allowBackup="false"` + `dataExtractionRules`（targetSdk 31+）空规则
- **涉及文件**：`app/src/main/AndroidManifest.xml`、新建 `res/xml/data_extraction_rules.xml`
- **前置**：无
- **验收点**：云备份 / `adb backup` 不含 App 数据

### B5 图标依赖瘦身

- **现状**：全量引入 `material-icons-extended`（约 20MB+）；当前仅用 `Edit` / `CheckCircle` / `Block`（MainScreen）、`ArrowDropDown`（TabActionBar）。
- **改动方案**：移除 `material-icons-extended`，改用：
  - Compose 默认包图标（`material-icons-core`，随 BOM 引入），或
  - 自定义 `ImageVector` 集中定义于 `ui/theme/AppIcons.kt`
- **涉及文件**：`app/build.gradle.kts`（删依赖）、`ui/main/MainScreen.kt`、`ui/main/tab/TabActionBar.kt`
- **前置**：无
- **验收点**：build 通过，三 Tab 图标正常显示

### B6 代码格式修正

- **现状**：`model/ImageListItem.kt` 第 3 行 `data class ImageListItem(    val id: String,` 括号内多余空格。
- **改动方案**：全量格式化（IDE Format / ktlint，若引入）
- **涉及文件**：`model/ImageListItem.kt` 等
- **前置**：无
- **验收点**：无 diff 噪音，格式统一

## 实施顺序建议

1. **阶段一（数据层）**：A4 → A3 → A1 → A5 → A2 → A6（Converters 与 Mapper 先行，Repository 接入后补 DAO 能力，最后响应式）
2. **阶段二（质量）**：B4 → B6 → B5 → B2 → B3（独立项先行，构建项放发布前）
3. **阶段三（测试）**：B1 随阶段一各步同步补（Mapper / Repository 先行）
4. **收尾**：每阶段完成更新架构设计 §3 数据流（目标 → 现状）、式样书开发记录、开发日志
