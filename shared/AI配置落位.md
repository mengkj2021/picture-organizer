# AI 配置落位（rules / prompts / skills / docs）

> **F30** 权威落位说明。维护入口仍是本目录；产品真相在 `docs/`，**不**整份复制进常驻 rules。  
> 口诀：`rules = 红绿灯`；`prompts = 这次怎么开车`；`skills = 某一类活的标准作业`；`docs = 地图与图纸（按需打开）`。  
> 规模变大时的扩大方向见 [`docs/工程/AI配置扩大方向.md`](../docs/工程/AI配置扩大方向.md)（demo 样板：架子在此，扩容看该文）。

## 1. 四象限

| 通道 | 何时用 | 体积 | 本仓库路径 |
|---|---|---|---|
| **rules** | 每票高频、几句说清、违了易出事 | 短；常驻注入 | `shared/rules/` → 同步 `.cursor` / `.codebuddy` |
| **prompts** | 端到端流程 + 填写区，拉入才跑 | 中 | `shared/prompts/` |
| **skills** | 可命名触发、可复用 SOP | 中长；按需 | `shared/skills/<name>/`（正文多由 F21/F22 等票落地） |
| **docs** | 式样 / 画面 / 设计 / 票库真相 | 可很长 | `docs/` — **只引用路径与章节，不塞进 rules** |

## 2. 判定标准（往哪放）

| 问自己 | → 落点 |
|---|---|
| 是否几乎每票都要、且能写成 ≤ 数条短句？ | **rules** |
| 是否「打开模板填票号就能跑完一条流水线」？ | **prompts** |
| 是否某一类重复活（新画面、对文档、改依赖）有固定步骤？ | **skills** |
| 是否产品规格 / 架构 / 验收细节？ | **docs**（配置里只写「去读哪个路径」） |

**禁止**：把式样书、画面 README、架构全文粘进 `alwaysApply` rules（违背 F24）。

## 3. 读文档策略（与 rules 短纪律一致）

1. 先票（或当前 prompt 填写区）→ 再票内**关联路径**  
2. 通读索引（`docs/README.md`）定位，**不通读**整库 docs  
3. 接票时列出「本票必读」路径/章节（见 `功能开发.md`），单次只打开清单内材料  
4. 需要时再横跳链接；历史与错题本按需取，不预装进上下文
