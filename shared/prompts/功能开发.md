# 功能开发

**用法**：把本文件拉进对话 → 填写下方「本次要开发」→ 发送。  
**约定**：本项目全部代码由 AI 开发；文档先行；式样书中「待定」项不得擅自实现。

---

## AI 执行流程（不用改）

收到「本次要开发」后，按序执行：

1. **读文档定边界**（按需，不要通读全库；分类见 `docs/README.md`）
   - `docs/式样/项目式样说明书.md` 相关章节
   - `docs/设计/架构设计.md`
   - `docs/工程/改动清单.md`（若需求相关）
   - 对应 `docs/画面/<画面>/README.md` 与相关区域文件；新画面先对照 `docs/设计/路由设计.md`、复制 `docs/画面/_模板/`
2. **对照需求**
   - 缺画面目录 / 区域文档 / 改动清单条目：先补文档，再写代码
   - 有「待定」或规格不清：先列出问题等用户确认，不要猜
3. **定点读码**：只读会改动的文件及同包相邻文件，禁止无目的扫全库
4. **方案与实现**
   - 默认：先列出拟改文件与验收点，等用户确认后再写代码
   - 若「本次要开发」写明 `直接实现`：跳过确认，直接改
5. **收尾**：实现后回写相关文档（画面 README / 区域文件、式样书、架构设计、改动清单、`docs/日志/` 等）；依赖变更同步式样书 §3.1

**硬性约束**

- 包结构遵循 `shared/rules/dev-convention.md`
- 新画面：先 `docs/画面/<画面名>/`（README + 按需区域文件），再 `app/src/...`
- route：全小写、多词连字符（见 `docs/设计/路由设计.md` 第 2 节）
