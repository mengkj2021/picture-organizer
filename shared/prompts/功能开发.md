# 功能开发（按票执行）

**用法**：把本文件拉进对话 → 在下方「本次接票」填票号与票目录 → 发送。  
**约定**：本项目全部代码由 AI 开发；**起票制**——任何改动必须先有票（票库 `docs/工程/票/`）；文档先行；式样书中「待定」项不得擅自实现；**一票一会话**（见 `shared/rules/dev-convention.md` 强制约定第 8 条：每票独立新会话，收尾完成后再接下一票）。

---

## AI 执行流程（不用改）

收到「本次接票」后，按序执行：

1. **读票定边界**
   - 读 `docs/工程/票/<分区>/<票号>-简述/README.md`：确认票号、类型、状态、现象 / 诉求、验收标准、**关联画面·预估**
   - 若给的票号不在票库 / 未起票：停下，请用户先按 `docs/工程/票/_模板/` 起票
2. **读文档定边界**（按需，不要通读全库；分类见 `docs/README.md`；落位见 `shared/AI配置落位.md`）
   - **本票必读清单**（先列出再打开；回复里可贴简表）：票「关联画面·预估」路径优先 + 本步将读的式样章节 / 画面区域文件 / 架构相关节；清单外默认不读
   - 若预估为空或明显不全：对照 `docs/画面/` 与路由补全预估后再读（回写票预估栏）
   - 常见候选（按票勾选，非全读）：`docs/式样/项目式样说明书.md` 相关章节；`docs/设计/架构设计.md` 相关节；对应 `docs/画面/<画面>/README.md` 与区域文件；新画面先对照 `docs/设计/路由设计.md`、复制 `docs/画面/_模板/`
3. **对照票内容**
   - 缺画面目录 / 区域文档 / 式样条目：先补文档，再写代码
   - 票上「待定」或规格不清：回票列出问题等用户确认，不要猜
4. **定点读码**：只读会改动的文件及同包相邻文件（`android/app/src/`），禁止无目的扫全库
5. **先测后写判断**（F20；依赖 F16 单测基础设施）
   - 问：本票改动是否含**可测纯逻辑**？
     - **触发示例**（命中任一即「是」）：重命名模板、标签/状态规则、筛选排序、日期解析、文件名规则；任意 `model/` / `util/` / `data` mapper 的规则改动
     - **豁免**（「否」）：纯 UI 壳层 / inset / 仅 Compose 结构改动、无 JVM 友好规则可抽——在方案或开发日志写明「无纯逻辑，未加测试」，不必硬造
   - **是** → 顺序强制：
     1. 先写或先补该逻辑的单测（路径与跑法见 F16 票开发记录）
     2. 再实现 / 改实现
     3. 收尾前跑相关测试（至少 `testDebugUnitTest` 中本票相关用例）须绿灯；测试与实现**同票提交**（测试改动极大时才另起测试票）
   - **否** → 跳过本步测试义务，直接进入方案与实现
6. **方案与实现**
   - 默认：先列出拟改文件与验收点，等用户确认后再写代码
   - 若「本次接票」写明 `直接实现`：跳过确认，直接改
7. **收尾**
   - **验收对照自评**（spec 审，**必须先于**回写 ✅）：读票「验收标准」每一条 → 按下表写证据（改了哪、验证了什么）→ **全部 ☑ 才可**回写 ✅ / 提交验收。任一条 ☐：先补做，再重做本步，禁止带缺口回写 ✅。含纯逻辑且已测的项，证据优先引用测试结果（命令与通过情况）。
     自评写入开发日志（可同时贴在回复里），格式：

     ```
     ### 验收对照自评（票号）

     | 验收项 | 结果 | 证据（改了哪 / 验证了什么） |
     |---|---|---|
     | （从票「验收标准」逐条抄录，勿改写） | ☑ | `path`：改了…；验证：… |
     | （下一条） | ☐ | （未达标则停，补做后再自评） |
     ```

     全部 ☑ 之后才进入下面的回写。
   - 回写票：状态（🚧 → ✅ / ❌）、开发记录；同步分区台账
   - **回写「关联画面 · 实际改动」**：列出本票改过的 `docs/画面/…` 路径（可到区域文件）；仅代码且文档已对齐则写「无需改文档」；预估有误可顺带订正预估栏
   - 补票内「完结复盘」（✅ / ❌ 后）：Bug 原因 / 式样利弊 / 调查结论 / 效果代价；有复用价值的教训登记 [`docs/工程/错题本.md`](../../docs/工程/错题本.md)（票内注明登记与否）
   - 回写相关文档：画面 README / 区域文件、式样书、架构设计、`docs/工程/票/改动清单.md` 总台账、`docs/日志/`（文件名带票号）
   - 依赖变更同步式样书 §3.1
   - **一票一会话**：本票收尾并提交后结束本会话；下一张票请用户**新开对话**再拉本提示词接票。同一票续接须先回写 🚧 进度再开新会话

**硬性约束**

- 包结构遵循 `shared/rules/dev-convention.md`（含第 8 条一票一会话）
- 新画面：先 `docs/画面/<画面名>/`（README + 按需区域文件），再 `android/app/src/...`
- route：全小写、多词连字符（见 `docs/设计/路由设计.md` 第 2 节）
- commit 信息与开发日志带票号（如 `Bug2 …`、`S2 …`）
