# 仓库结构总览（AI 开发层）

> 写给 AI / 新人：**不是** `android/` 包树，而是整仓「用 AI 开发 App」的外壳结构。  
> **给人看的整体系整合**：[AI开发体系总览.md](AI开发体系总览.md)。  
> 包结构见 [`project-docs/架构设计.md`](../../project-docs/架构设计.md) §2。

## 一句话

本仓库 = **AI 开发操作系统**（怎么接票、读什么、改什么、写回什么）+ **Android 工程**（唯一代码产物）。

## 总览图

```
picture-organizer/                    ← 仓库根（门面 README）
│
├── 【项目真相 · 读/写】
│   ├── project-docs/                 ← android 已落地规格镜像
│   └── project-status/               ← 票库 · 是否实现 · 阶段
│
├── 【代码目标 · 只改这里的业务】
│   └── android/                      ← Gradle 工程（可独立打开）
│
├── 【AI 怎么干活】
│   ├── prompts/                      ← 拉入对话的编排壳（扁平：`用途_文件名.md`）
│   ├── shared/                       ← rules / skills 编排壳 → 同步到工具
│   │     └── rules/ · skills/
│   ├── ai-workbench/                 ← 宪法 · 细则 · 模板 · 指南（本目录）
│   ├── .cursor/ · .codebuddy/        ← 工具实际读取（从 shared 同步）
│   └── .githooks/                    ← push 前门禁（如 ktlint）
│
└── README.md
```

## 闭环（必须记住）

```
prompts/ + shared/  ──▶ include──▶  ai-workbench/
        │
        ▼ 读
project-status/ + project-docs/
        │
        ▼ 改
android/
        │
        ▼ 写回
project-status/ + project-docs/
（过程写在票内复盘；不另建 logs）
```

权威闭环与分层：[`../宪法/文档分层约定.md`](../宪法/文档分层约定.md) §0。  
▶ include 语义：[`../宪法/include约定.md`](../宪法/include约定.md)。

## 各目录「回答什么」

| 目录 | AI 该用它回答 | 禁止 |
|---|---|---|
| `project-docs/` | App **现在**长什么样、route、画面、Room… | 未决愿望、排期 |
| `project-status/` | 做到哪、哪张票、是否实现、阶段；**过程也在票里** | 画面规格正文 |
| `android/` | 真相源码 | — |
| `prompts/` | 这次跑哪条流水线 | 细则长文（在 workbench） |
| `shared/` | 常驻纪律 / 技能壳 | 产品规格 |
| `ai-workbench/` | 宪法、细则、模板、**本指南** | 票正文、画面规格正文 |

## 接票最小读法

1. 票：`project-status/票库/<分区>/<票号>-简述.md`
2. 是否实现：`project-status/阶段/*/待对应.md` + 票内状态（按需）
3. 规格：按票「关联画面」打开 `project-docs/` 对应文件（见 [如何使用-project-docs.md](如何使用-project-docs.md)）
4. 流程：`prompts/票_接票开发.md`（会 include 细则）
5. **不通读**整库
