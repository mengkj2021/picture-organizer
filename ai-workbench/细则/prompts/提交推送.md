# 提交推送 · 细则

> 供 `prompts/git_提交推送.md` ▶ include。  
> **拉入本壳并发送 = 用户授权：提交并推送当前全部相关变更**（填写区可空）。

▶ include `ai-workbench/细则/rules/git约定.md`

**目的**：按纪律完成 `status → add → commit [-F] → push`，避免中文乱码与误加文件。

## 流程

1. **读意图**  
   - 默认：**全量相关变更 + commit + push**  
   - 填写区写了「不推送」→ 只 commit  
   - 「不纳入本次」列出的路径跳过  
   - 票号：填写区优先，否则从 diff / 会话推断；仍无则先问再继续

2. **摸清状态**（可并行）  
   - `git status`  
   - `git diff` / `git diff --staged`  
   - `git log -5 --oneline`（对齐说明文风）

3. **暂存**  
   - **禁止** `git add .` / `git add -A`  
   - 按 `status` 中的修改 / 新增 / 删除，用**目录或文件路径**逐项 `git add`（中文路径用目录级 add 或引号）  
   - 排除：密钥、`local.properties`、`build/`、`.gradle/`、意外产物、填写区「不纳入本次」  
   - **不等二次确认**（拉入本壳即授权）；若只有「不应提交」类文件则停并说明

4. **写提交说明并 commit**  
   - UTF-8 **无 BOM** 写入仓库根 `提交说明.txt`（票号 + 为何改，1～2 句）  
   - **禁止** `git commit -m "中文"`；用 `git commit -F 提交说明.txt`  
   - 成功后删 `提交说明.txt`；`git log -1` 确认中文；乱码且未 push → 按 git 约定 amend `-F`

5. **推送**（默认执行；「不推送」则跳过）  
   - 合入方式：`direct-main` 推当前分支；`via-mr` 按约定开 PR  
   - `git push`；**禁止** `--force` / `--no-verify`（除非用户明确要求）  
   - pre-push / ktlint 失败 → 修或回报，不偷偷跳过

6. **收尾**  
   - 提交 hash、说明全文、已推送与否、工作区是否干净  
   - 有意排除或未纳入的本地改动 → 列出

## 硬性约束

- 本壳拉入即授权本次提交（及默认推送）；其它对话仍不主动 commit / push  
- 不 `git add .`；不擅自 force push；不把密钥 / 构建产物打进提交  
- Windows 中文说明必须走 `-F` 文件
