# 交叉审查 · 细则

> 供 `prompts/票_交叉审查.md` ▶ include。可选工具，不进接票开发强制流程。

**目的**：写与审换脑，抓多余抽象、包结构不符、边界缺口、验收跑偏、改动漂移。

1. **锁定对象**：读填写区与票 README（验收标准逐条）；缺则停
2. **定点读改动**：只读列出的文件及票复盘点名路径；对照架构 §2 / 画面 README 按需；禁止扫全库、禁止借审重写
3. **固定清单**（每条必须给结论）

   | # | 审查项 | 关注点 |
   |---|---|---|
   | ① | 多余抽象 / 造轮子 | 不必要的层、重复 util/Repository |
   | ② | 包结构与现有模式 | 架构 §2、同包写法、规则/文档同步 |
   | ③ | 边界与错误分支 | 空值、失败、权限/IO、取消、平台差异 |
   | ④ | 对照验收标准 | 是否就是票要的事 |
   | ⑤ | 改动漂移 | 范围外改动、顺手重构 |

4. **输出格式**（全部「通过」才可写「审查通过」）

```
## 交叉审查结果（票号）
- 实现方 / 审查方 / 审查对象：…
| # | 审查项 | 结论 | 说明 |
|---|---|---|---|
| ①…⑤ | … | 通过 / 问题 | … |
### 总评
- 审查通过｜有问题待改
- 建议回写：原票开发记录 / 或起 Bug 票
```

5. **收尾**：默认只输出结果；填写区写 `审完可改` 则只修「问题」项并补复审表；不把票标 ✅

**硬性约束**：不做 CI、不擅自改接票开发强制步骤；结论可定位；无依据不标「问题」。
