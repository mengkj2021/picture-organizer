# 拉取最新代码 · 细则

> 供 `prompts/git_拉取最新代码.md` ▶ include。

▶ include `ai-workbench/细则/rules/git约定.md`

**目的**：把远程最新变更安全合入当前工作区，先披露风险再动手。

## 流程

1. **读填写区**  
   - 远程默认 `origin`；分支默认当前分支  
   - 策略默认 **merge**（`git pull`）；仅当填写区写 `rebase` 才用 `git pull --rebase`（或等价 fetch + rebase）

2. **摸清本地**（拉之前必做）  
   - `git status` · `git branch -vv`  
   - 是否有未提交改动、未推送提交、是否 behind/ahead  
   - `git fetch`（先取对象，不改工作区）后看 `git log HEAD..@{u}` / `@{u}..HEAD`（无上游则说明）

3. **未提交改动时**  
   | 填写区 | 行为 |
   |---|---|
   | 空 /「停下来说明」 | **停**：列出脏文件与建议（提交、stash、或丢弃须用户亲口确认） |
   | 「先 stash 再拉」 | `git stash push -u -m "…"` → 拉 → `stash pop`；冲突则停并说明 |
   | 「直接拉」 | 仅当 AI 判断与将合入文件无重叠或用户已知风险；否则仍停 |

4. **执行拉取**  
   - merge：`git pull`（或 `git pull origin <branch>`）  
   - rebase：`git pull --rebase`（有未推送本地提交时提醒 rebase 改写历史；已共享分支谨慎）  
   - **禁止**：`reset --hard`、`push --force`、删除用户未确认的本地提交/文件

5. **冲突**  
   - 停；列出冲突文件；默认不擅自选一边；请用户决定或开票解决  
   - 勿在冲突未解时 push

6. **收尾输出**  
   - 当前分支、与远程相对位置、本次合入的简要 log、工作区是否干净  
   - 若 stash 过：是否已 pop、是否有 stash 残留

## 硬性约束

- 拉取前必须 `status`（及必要的 `fetch`）  
- 不擅自丢弃本地提交或未提交改动  
- 不 `--force`；不把 pull 失败假装成功
